# Evidence

Every artifact here is regenerated by one committed script. From the repo root:

    node promotion/evidence/audit.mjs

Needs network. It downloads its two tools with `npx --yes` at the pinned
versions below; this pack keeps no `package.json` and gains none by running it.
Pass `--attribute-only` to redo the offline analysis without re-running the two
browser audits.

| Artifact | What it answers | Scorecard rows |
|---|---|---|
| `surface-inventory.json` | Does this repo author a rendered surface at all? | 3, 7, 8 |
| `wig-review.json` | Web Interface Guidelines review of the authored content | 7 |
| `rendered-defect-check.json` | Are the ledger's defect fixes live in the served HTML? | 2 |
| `test-run.json` | Does the repo's own guard run green? | 11 |
| `axe-fullpage.json` | Raw axe-core output, unedited | 6, 8 |
| `lighthouse-github-readme.json` | Raw Lighthouse output, unedited | 8, 9, 10 |
| `attribution.json` | Who owns each finding the two audits produced? | 6, 8, 9, 10 |

The two raw JSONs are large (~1.8 MB each) and committed unpruned on purpose. A
trimmed audit output invites exactly the question this directory exists to
settle, and 3.6 MB is a cheap price for an artifact nobody has to take on trust.

## The one that matters

`attribution.json` is the point, not the scores.

Conditions 7 and 8 ask about a web interface. This pack is markdown, so the only
page that exists is github.com rendering it, and an audit pointed there grades
GitHub's application. Saying so is a claim. Running the audits anyway and then
resolving every finding to the host that served the offending bytes is evidence:
29 findings, 0 reachable by anything this repo ships.

That is why the good numbers in `lighthouse-github-readme.json` — accessibility
97, best-practices 100 — are not in a PASS row.

## A zero needs a control

`surface-inventory.json` carries a `positiveControl` field, and the script exits
non-zero rather than writing evidence if it fails.

The first version of this script built its git pathspecs through a shell.
`git ls-files '*.html'` returns matches under bash and nothing under cmd.exe,
which does not strip the quotes — so it wrote `renderableSourceFileCount: 0`
into a receipt, a zero that meant "the command did not run" while reading
exactly like "the repo has no UI". The whole not-applicable verdict for
conditions 7 and 8 rested on that number. It now goes to git as argv, and
`git ls-files *.md` must return non-zero in a markdown-only repo before any
count below it may be believed.

## Pinned tools

    npx --yes @axe-core/cli@4.13.0 <url> --save <file>
    npx --yes lighthouse@13.4.1 <url> --output=json --output-path=<file> --chrome-flags="--headless"

Both commands live verbatim in `audit.mjs` and are echoed into
`attribution.json`, so the artifact and the command that made it cannot drift.
